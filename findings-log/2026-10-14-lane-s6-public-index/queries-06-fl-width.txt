# ROUND 3 — why does `fl=url` return FEWER records than `fl=url,timestamp,...`?
#
# THE CONTRADICTION (all OBSERVED, ledger seq 68 and seq 102, same crawl, same
# url, same matchType, same API, same host, same run-day):
#
#   fl=url,timestamp,status,mimetype  -> 11522 records, 1864922 B, 37 hosts
#   fl=url                            ->  5108 records,  655360 B,  2 hosts
#
# A byte ceiling predicts the OPPOSITE. `fl` cannot change which records MATCH
# -- it chooses which fields each record carries -- so narrowing the fields makes
# each record smaller, which should let MORE records fit under any byte ceiling.
# Narrow returned 5108, fewer than medium's 11522. So either there is no byte
# ceiling and `fl` is changing the match, or the ceiling is not a function of
# bytes.
#
# The 5108-record body is exactly 655360 B = 640 KiB and ends on a clean record
# boundary at `.../deep-brain-stimulation-dystonia/about/getting-dbs.html`, which
# is a very round number for a coincidence. Its host set is
# {medtronic.com, www.medtronic.com} -- and in SURT order the other 35 hosts
# (ambassador, bakkeninvitation, ...) sort BEFORE www.medtronic.com, so a
# complete SURT-ordered stream that reached www.medtronic.com should have carried
# them. It did not. That is a second reason the narrow response cannot simply be
# a truncated prefix of the medium one.
#
# Three ways this could be, and one request each:
#   A  re-issue fl=url            -> same 655360 B again = deterministic ceiling;
#                                   different = time- or load-dependent
#   B  fl=url,timestamp           -> an intermediate width. Monotone
#                                   (5108 < X < 11522) says width drives it.
#                                   Not monotone says fl changes the match.
#   C  fl=url,status              -> a second narrow point, to tell (A)'s
#                                   "deterministic" from "coincidentally equal"
#   D  the 32 KiB cell, narrowed  -> 2022-40/medtronic.com read 32768 B / 203
#                                   records at MEDIUM. If narrow reads MORE than
#                                   203 there, the 203 was a floor. If it also
#                                   reads 32768 B, the ceiling is per-response
#                                   and identical at both sizes, which is a
#                                   different rule again.
#   E  the pages=3 cell, paginated -> 2022-40/medtronic.com reports pages=3,
#                                   blocks=14 -- the only cell in the repo where
#                                   pages is not 1. Pages 0..3 settle whether the
#                                   set really spans 3 pages.
#
# DELAY=10. Eight of fifteen requests answered 502/504 at 2.5 s and four of
# eleven at 8 s. A 502/504 is a failure and never an absence.
